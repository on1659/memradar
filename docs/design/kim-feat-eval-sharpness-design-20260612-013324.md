## Problem Statement

memradar 메인 대시보드 14카드 + 성장 섹션 4카드 중 일부가 "한 번 보고 끝"인 상태다. 사용자가 직접 지목한 불만 두 가지:

1. **활동 패턴 카드 중복** — "활동히트맵이나 활동밀도, 요일별패턴등이 좀 겹치는느낌" (사용자 발언). 셋 다 "언제 일했나"를 다른 모양으로 반복한다.
2. **토큰 피크일 카드의 낮은 정보가** — "토큰 가장 많이, 적게 사용한 날 이런거 좀더 좋은걸로". 날짜 하나는 trivia이고 스토리가 없다.

배경 제약: 홍보를 앞두고 있고, 공유물 동질화(누구나 비슷한 결과)가 바이럴의 적이라는 진단이 이미 승인돼 있다 (prelaunch-goaldoc G3). wow 대상은 "둘 다, 공유 우선" (회고 + 스크린샷 공유, 공유 우선).

## What Makes This Cool

대시보드의 정체성이 "분석 도구"에서 **"AI 협업 지문(fingerprint)"**으로 이동한다. 핵심 질문이 "얼마나 썼나"에서 **"AI랑 일할 때 나는 어떤 개발자인가"**로 바뀐다. 모든 신규 카드는:

- **lift 기반** — raw 카운트가 아니라 본인 기준선 대비 편차를 보여줘서 사람마다 결과가 달라진다 (공유 다양성)
- **영수증(receipts) 동반** — 모든 주장 옆에 실측 수치 2~3개 (반증가능 출력 원칙, kim-master-design 2026-05-23 APPROVED 연장)
- 상용 통계(합계·토큰·모델)는 스토리가 아니라 스토리를 받치는 접힌 영수증으로 강등

## Constraints

- **세션 데이터 외부 전송 금지** (CLAUDE.md) — 모든 계산은 로컬 순수 함수, LLM 호출 없음
- **Wrapped 슬라이드 8장 고정**, `ToolsSlide.tsx` import 금지 — 이 작업은 Dashboard 영역만
- 사용자 프롬프트 **원문 인용 금지** — 시크릿 마스킹 표면 확장 방지 (성장 섹션·코칭 카드와 동일 원칙)
- 단정 판정 금지 — 확정 어조 라벨 대신 분포/두드러진 패턴 + 추정 명시 (ba88105 재포지셔닝, 분류기 정확도 37.8% 교훈)
- 임계값·스코어 가중치는 잠정값 원칙 (AI-ROLE-SCORING-REDESIGN §2)
- 결과물은 goaldoc까지 — 이 세션에서 구현하지 않음

## Premises (모두 사용자 합의, 2026-06-12)

| # | 전제 | 합의 |
|---|------|------|
| P1 | 카드 가치 = "내 얘기다" + "스크린샷 한 장으로 공유된다". 합계·시간 통계는 commodity, AI 협업 방식 카드가 moat | ✅ |
| P2 | 히트맵·활동 밀도·요일별 패턴 3장은 1장으로 통합한다 | ✅ |

| P4 | 새 카드는 전부 lift(기준선 대비) + 반증가능(실측 수치 인용) 형식 | ✅ |

## Cross-Model Perspective

Codex (gpt-5.5, 독립 콜드 리드) 핵심:

- **"AI Collaboration Fingerprint"** 프레임 — 모든 카드를 행동 편차(behavioral deviation) 카드로, commodity 지표는 접히는 영수증으로. 본 세션의 EUREKA·P1과 독립적으로 동일 결론.
- **주말 빌드 우선순위**: 14장 재설계가 아니라 3장 수직 슬라이스 — ① 활동 통합 "Your Coding Rhythm" ② 피크일 교체 "The Day Your Agent Earned Its Keep" (토큰 최대가 아니라 *서사 점수* 최대인 날) ③ 정체성 카드 "AI Collaboration Archetype"
- 카드 아이디어 12종 제안 (Prompt Accent, Friction Index, Context Appetite, Recovery Pattern, Collaboration Balance, Hidden Superpower 등) — 후속 사이클의 후보 풀
- Claude 반대 의견 (반영됨): ⑩ "Most You-coded Sentence"(프롬프트 원문 인용)는 시크릿 마스킹 표면 확장으로 **제외**. ① Archetype 단정 라벨("You are a Refactor Sprinter")은 단정 판정의 부활 — **분포형 + 추정 명시로 톤 다운**. "성공 세션" 류 outcome proxy는 정의 미해결 — open question으로 유보.

## Approaches Considered

### Approach A: 수직 슬라이스 3+1 (선택)
죽은 카드 2구역을 직접 대체하는 핵심 3장 + receipts 패턴 도입.
- Effort: M (human: ~2주 / CC: /goal 3~4사이클 — W1~W4가 각각 COMPLEX~STANDARD 1사이클) · Risk: Low-Med
- Pros: 지목된 불만 정면 해결, lift 형식 소면적 검증 (리스크 분리·검수 가능성), goaldoc 작업 항목 W1~W4로 분해 가능
- Cons: commodity 카드 일부 잔존 (후속에서 정리)
- Reuses: 성장 섹션의 텍스트 전처리(`stripMarkup`/`countWords`/`isStructured`)와 `RETRY_MARKERS` 사전, prelaunch-goaldoc G3(분류기 lift) 작업 예정분과의 방향 정합, html-to-image (ShareSlide). 단 per-day 집계는 신규 경로 (공통 데이터 정책 2항)

### Approach B: 전면 lift 전환
baseline 모듈(개인+합성 코퍼스 기준선) 선행 구축 후 14장 전부 deviation+receipts로 재편.
- Effort: XL (human: ~2달 / CC: 4~6사이클) · Risk: Med-High
- Pros: 일관된 2층 정보 구조, 구조적 차별화 완성
- Cons: prelaunch-goaldoc G3(분류기 lift) 미완 위에 짓는 순서 역전, 회귀 면적 큼
- → **후속 단계로 유보.** A에서 검증된 lift 패턴 + prelaunch-goaldoc G3 완료 후 진행.

### Approach C: 공유 빌더 우선
카드 조합 → 1장 PNG export 빌더를 1급 기능으로.
- Effort: M-L · Risk: Med
- Cons: 콘텐츠 개선 없이 도구만 좋아지는 본말전도 위험 → 카드별 단독 export만 A에 흡수, 조합 빌더는 보류.

## Recommended Approach

**A: 수직 슬라이스 3+1.** 카드 구성:

### 카드 1 — 코딩 리듬 (활동 3장 통합)
- 히트맵 + 활동 밀도 + 요일별 패턴 → 1장. 컴팩트 캘린더(기존 히트맵 베이스) + **한 줄 리듬 서사** (권장 어조 예: "심야 폭주형으로 보여요 — 22~01시 세션이 본인 평균의 2.8x") + 영수증(요일 분포·밀도 수치는 카드 내 보조 행 또는 접힘).
- 리듬 라벨은 본인 시간 분포의 편차에서 도출 (요일 lift, 시간대 lift). 라벨 사전은 잠정 6~8종, 단정 어조 금지 ("~형으로 보여요").
- **연속 기록(streak) 카드도 카드 1의 영수증으로 흡수** — "언제 일했나" 계열이므로 같은 카드의 보조 수치(최장 연속 N일)로 강등. `dashboard-activity-grid`의 4장(히트맵·연속 기록·활동 밀도·요일별)이 카드 1 하나가 된다.
- 시간대별 활동(24h 바)은 별도 카드로 잔존 — 통합 대상이 아님 (v1 유지, B단계 재평가).
- **빈상태/최소 표본**: 관측 활동일 < 7일이면 리듬 라벨 미표시, 캘린더+수치만. (가드 상수는 잠정값)

### 카드 2 — 그날 이야기 (토큰 피크일 교체)
- "토큰 최대인 날"이 아니라 **서사 점수 최대인 날**. 기존 카드의 최다/최저 토글·핀 인터랙션은 **카드 2로 대체되며 제거** (최저 토큰일 데이터는 영수증에도 싣지 않음 — trivia 판정).
- **서사 점수 결합 구조** (가중치 수치만 잠정, 구조는 확정):
  - 항별 0~1 정규화 후 **가중합**. 항: ① 토큰 이상치(그날 토큰 / 본인 일평균, cap), ② 세션 밀도(그날 세션 수 + 그날 첫~마지막 메시지 시간 범위), ③ 재질문 회복(그날 전반부 vs 후반부 retry 비율 하락폭), ④ 작업 다양성(그날 사용 스킬·언어 종수).
  - **결측 항은 제외하고 남은 가중치 재정규화** — 예: 그날 follow-up 0건이면 ③ 제외, Codex-only 날이면 ④의 스킬 종수 제외(언어 종수만).
  - **source-aware**: 스킬 종수는 `<command-name>` 기반이라 Claude 전용 — Codex-heavy 사용자가 체계적으로 불리해지지 않도록 buildGrowth의 proxy C 제외 패턴을 따른다.
- **최소 표본 가드**: 그날 user 메시지 < 10건이면 후보 제외. 재질문 회복 항은 그날 follow-up ≥ 10건일 때만 산입하고, **영수증에 분모 표기 필수** ("재질문률 28%→9% (n=32)").
- 출력: 날짜 + 그날의 패턴 요약 + **세션 리스트로 점프**: 카드 클릭 시 세션 리스트 섹션으로 스크롤 + 해당 날짜 필터 적용 (경량 신규 상태 1개 — 기존 검색 필터 패턴 재사용, 정확한 결합은 Scout 확정).
- 사람마다 "마이그레이션의 날"/"버그 사냥의 날"이 달라짐 — 공유 다양성 충족.
- **빈상태**: 활동일 < 7일이면 카드 전체 "이야기 모으는 중" 빈상태.

### 카드 3 — AI 협업 지문 (신규 정체성 카드)
- 상단 overview 그리드에 추가. **단일 라벨이 아니라 top lift 2~3개의 분포형 제시**.
- **기존 정체성 카드 2장과의 경계**: 성격 카드 = "어떤 사람인가(작업 스타일)", AI 역할 도넛 = "AI에게 무엇을 시키나(요청 주제)", **지문 카드 = "AI와 어떻게 협업하나(상호작용 방식)"** — 셋이 답하는 질문이 다르며, 지문 카드는 상호작용 행동 신호만 쓴다.
- **신호별 lift 정의 표 (v1 후보 — 분자/분모를 명시해야 구현 착수 가능):**

| 신호 | 분자 | 분모 (본인 기준선) |
|---|---|---|
| 주말 집중 | 주말 일평균 세션 수 | 주중 일평균 세션 수 |
| 구조화 프롬프트 | 최근 30일 구조화 비율 | 이전 전체 기간 구조화 비율 (%p 차) |
| 정정 후 계획 요청 | 정정 직후 메시지 중 계획 요청 비율 | 전체 메시지 중 계획 요청 비율 |
| 심야 비중 | 22~02시(로컬) 메시지 비율 | 전체 시간대 균등 기대치 |
| 긴 세션 선호 | 21턴+ 세션 비율 | 본인 세션 길이 분포 중앙값 기대 |

- **"계획 요청" 감지는 신규 마커 사전 제작이 필요** (RETRY_MARKERS처럼 고정 사전 — "계획", "plan", "어떻게 할지", "방향" 등. 기존 코드에 없음을 명시). v1에서 사전 품질이 안 나오면 이 신호는 빼고 출시 — 신호 5종 중 3종 이상만 성립하면 카드 성립.
- 데이터 소스: 성장 섹션 산출물 + 활동 리듬 + 신규 per-day 집계. **외부/합성 코퍼스 기준선은 쓰지 않음** (그건 분류기-lift·B단계 소관) — v1은 "본인의 다른 기간/전체 평균 대비" lift만.
- 추정 명시 부제 필수. **최소 표본**: 신호별 분모 n < 30이면 해당 신호 제외, 성립 신호 < 2개면 "지문 수집 중" 빈상태. 영수증에 n= 표기.

### 카드 4(패턴) — 영수증 접힘 + 카드 단독 PNG export
- 신규 카드 3장에 공통: 주장 문장 옆 실측 수치(비율은 분모 n= 동반), 상세 수치는 접힘(receipts).
- 카드별 단독 PNG export 버튼 (html-to-image 재사용) — 시크릿 마스킹 적용 후 렌더.

### 공통 데이터 정책 (구현 전 확정 사항)

1. **일(day) 경계 = 로컬 날짜.** 기존 `dayKey`는 `toISOString().slice(0,10)` UTC라 KST 사용자의 00~09시 활동이 전날로 귀속된다 — "심야 폭주형"일수록 카드 1 요일 lift·카드 2 "그날" 묶기·카드 3 주말/심야 신호가 모두 왜곡되므로, 신규 카드의 일 단위 집계는 **로컬 날짜 키(`toLocalDayKey` 신설)** 를 쓴다. UTC dayKey를 쓰던 히트맵·요일 카드는 카드 1로 대체되므로 신구 불일치 면이 같이 제거된다 (카드 1 캘린더도 로컬 키 기준, 기존 24h 바의 로컬 `getHours()`와 정합). 월 버킷(`toMonthKey`, UTC)은 성장 섹션 소관이라 이번에 건드리지 않음 — 일/월 기준 차이는 영수증 툴팁에 명시.
2. **per-day 집계는 신규 경로다.** 기존 `GrowthStats.retryStats`는 전체 기간 단일 합산이라 카드 2의 "전반→후반 retry 하락"과 카드 3의 기간별 lift에 재사용 불가. 실제 재사용 가능한 것은 `RETRY_MARKERS` 사전·`isStructured`·`stripMarkup`·`countWords` 수준이고, `matchRetryMarker`는 module-private이므로 export 승격이 필요하다. per-day 빌더(`buildDailyCollab` 가칭)는 신규 작성.

3. outcome proxy("성공 세션") 정의 — 미해결, 이번 범위 제외
4. 통합 후 영수증으로 강등되는 수치(활동 밀도·요일 분포·streak)의 표시 위치 — 카드 내 접힘 vs 툴팁
5. "계획 요청" 마커 사전의 변별력 — W3에서 사전 제작 후 미달 시 해당 신호 드롭 (카드 성립 조건은 신호 3종 이상)

## Success Criteria

- 사용자 지목 불만 2건 해소: 활동 패턴 3장 → 1장, 토큰 피크일 → 서사 카드
- 신규 카드 3장 전부 lift 수치 + 영수증 포함, 단정 어조 0건 (카피 검수)
- **"내 얘기" 테스트**: 서로 다른 실데이터(또는 합성 페르소나 픽스처) 2벌에서 카드 3장의 출력이 서로 명확히 달라짐 (동질화 회귀 테스트)
- 카드별 PNG export 동작 + 시크릿 마스킹 적용 확인
- 기존 테스트 하네스 전체 그린, Wrapped 8장 무변경

## What I noticed about how you think

- "보고 아닌거같으면 냅둬도돼"라고 위임하면서도, 전제 확인 단계에선 "p1~p5 요약해서 먼저보여줘"라고 멈췄다 — 실행은 위임하되 방향 합의는 직접 확인하는 패턴. 합의 비용을 아끼지 않는 건 goaldoc 기반 워크플로우와 잘 맞는다.
- 외부 검색을 거절했다 ("건너뛰기 — 로컬만") — 프라이버시가 제품 셀링 포인트인 도구를 만들면서 본인 세션에도 같은 기준을 적용하는 일관성.
- 불만을 카드 이름이 아니라 **중복이라는 구조적 단어**로 표현했다 ("의미가 중복되는것들") — 개별 카드가 아니라 정보 구조 차원에서 보고 있다는 신호. 이번 재편의 EUREKA(통계 축적이 아니라 구조 전환)는 사실 그 발언에서 시작됐다.

즉 한 대화 안에서도 질문마다 다른 모델이 답할 수 있습니다. 실제로 그랬고요.

2그래서 뭐가 문제인가

Claude Code는 모든 대화를 파일로 남깁니다. 그 파일에는 AI가 답한 줄마다 “어떤 모델이 답했는지”가 하나하나 적혀 있습니다. 데이터는 이미 완벽하게 있습니다.

문제는 memradar가 그걸 읽는 방식입니다. memradar는 대화 파일을 열어서 맨 처음 발견한 모델 이름 하나를 그 대화 전체의 이름표로 붙이고 끝냅니다. 나머지는 버립니다.

79
모델 정보가 있는 전체 대화
38
실제로는 2개 이상 모델을 쓴 대화
48%
그래서 이름표가 틀린 비율

결과적으로 “당신이 가장 많이 쓴 모델” 통계가 틀립니다. 위 대화의 경우 opus-5로 답한 99줄은 통계에서 아예 사라집니다. 연말 결산 화면(Wrapped)과 대시보드가 모두 이 틀린 숫자 위에 서 있습니다.

3고치려고 열어봤더니

바로 고치려다가, 잘못 고칠 위험이 커서 서로 다른 관점의 검토자 4명 + 교차 심문관 1명에게 제 수정 계획을 공격하게 했습니다. 결과적으로 제 초안의 전제 4개가 실제 데이터로 반박당했습니다. 큰 것부터:

① 계산기가 두 대 있었다

대화 파일을 읽는 코드가 두 벌 존재합니다. 제가 고치려던 쪽은 개발용이고, 사용자가 실제로 쓰는 경로는 다른 쪽이었습니다. 한 쪽만 고쳤으면 겉보기엔 고쳤는데 실제 제품에선 아무것도 안 바뀌는 상태가 됐을 겁니다.

② “몇 번 답했나”를 셀 방법이 없었다

가장 중요한 발견입니다. “AI가 몇 번 답했나”를 세려고 보니, 코드 안에 그걸 셀 수 있는 단위 자체가 없었습니다. 이건 아래 4장에서 따로 설명합니다.

③ 범인이 딴 데 있었다

“하루에 모델을 몇 종류 썼나”를 재는 기능이 이미 오염돼 있었습니다. 저는 원인을 <synthetic>(중단·한도초과 같은 시스템 메시지)이라고 짚었는데, 실제로 재보니 그걸 빼도 결과가 단 하루도 안 바뀌었습니다. 진범은 따로 있었습니다 — 내가 쓴 질문에까지 AI 모델 이름을 붙이던 코드였습니다.

④ Codex는 반대 방향으로 틀려 있었다

Claude 대화는 “처음 만난 모델”을 이름표로 쓰는데, Codex 대화는 “마지막에 만난 모델”을 씁니다. 방향이 정반대입니다. 그래서 Codex 대화 4개는 단 한 번도 답한 적 없는 모델이 그 대화의 이름표로 붙어 있습니다.

이 4개는 전부 제가 “이미 확인했다”고 믿었던 부분입니다. 검토를 안 붙였으면 그대로 잘못 고쳤을 겁니다.

4“한 번 답했다”를 세는 게 왜 어려운가

이게 아까 제가 어렵게 물어봤던 것의 배경입니다. AI가 한 번 답할 때, 파일에는 이렇게 기록됩니다:

나
이 버그 고쳐줘
AI
(생각 중…)  ← 1줄
AI
파일을 읽습니다  ← 1줄
AI
코드를 고칩니다  ← 1줄
AI
“고쳤습니다”  ← 1줄

사람이 보기엔 “한 번 답한 것”인데 파일에는 4줄로 적혀 있습니다. 그래서 “몇 번 답했나”를 세는 방법이 세 가지가 되고, 셋이 전부 다른 숫자를 냅니다.

세는 방법무슨 뜻결과판정
줄 단위 파일에 적힌 줄을 그대로 셈 한 번 답한 게 평균 1.78줄로 쪼개짐 기각
Codex는 이렇게 안 쪼개서, 모델 실력이 아니라 기록 방식 차이가 1등을 정해버림
덩어리 단위 memradar가 연속된 줄을 하나로 합친 것 13.17배로 접힘 기각
접히는 정도가 모델마다 다름 — haiku 4.05 vs opus-5 15.23, 3.76배 차이. 어려운 일에 쓴 모델일수록 손해를 봄
응답번호 단위 “이 답변 한 번”에 붙는 고유번호로 셈 쪼개짐도 접힘도 없음 채택
직접 재검증함 — 필요한 응답 전부가 이 번호를 갖고 있고, 없는 28건은 모두 집계 대상이 아닌 시스템 메시지

세 번째 방법으로 확정했습니다. 나머지 둘은 “열심히 일한 모델일수록 적게 세지는” 편향이 있어서 정확한 통계를 만들 수 없습니다.

5이미 정해진 것

✓
세는 단위 — “AI가 몇 번 답했나”(응답번호 기준). 대화 수도 토큰 수도 아님
✓
Wrapped 연말결산 — Claude와 Codex를 합친 통합 1위를 그대로 표시. 대신 대시보드는 소스 필터를 지키도록 버그 수정 (지금은 Claude만 보겠다고 걸러도 도넛에 gpt가 남아 있음)
✓
모델이 바뀐 이유 — “사용량 한도”처럼 분류 이름만 표시. 원문에 “resets 4:20am (Asia/Seoul)” 같은 타임존이 들어 있어 그대로 내보내지 않음
✓
작업 순서 — 8단계로 쪼개서 각 단계마다 되돌릴 수 있게. 첫 단계는 코드를 안 건드리고 테스트만 현실에 맞게 고치는 것

6남은 결정 — 이것만 정해주시면 됩니다

결정 A

대화를 읽을 때 “여기서 모델 바뀜” 표지판을 몇 개나 세울까요?

대화를 위에서 아래로 읽다 보면 중간에 모델이 바뀝니다. 그 지점에 이런 표지판을 넣으려고 합니다:

나
이거 고쳐줘
AI
네, 고쳤습니다
여기부터 Opus 5
나
이것도 확인해줘
AI
확인했습니다

얼마나 자주 바뀌는지 실제로 재봤습니다:

34
모델이 섞인 대화
18
그중 2번 이상 바뀐 것
14
가장 많이 바뀐 대화의 전환 횟수
(약 3~4개 메시지마다 표지판 하나)

모든 전환에 표지판

→ “전부 다 세워”

  • 정확함 — 어느 답변이 무슨 모델인지 표지판만 보고 정확히 알 수 있음
  • 패턴이 보임 — 왔다 갔다 한 흔적이 그대로 드러남
  • 가장 심한 대화에선 표지판이 14개

각 모델 첫 등장에만

→ “처음 나올 때만 세워”

  • 깔끔함 — 대화당 최대 4개
  • 부정확해짐 — A→B→다시 A로 돌아온 구간을 표현 못 함. 그 구간은 표지판만 보면 B로 오독됨
  • 정확히 알려면 마우스를 올려봐야 함

참고로 표지판은 눈에 튀지 않는 회색 계열로 정해져 있습니다 — 초록·보라 같은 색은 이미 다른 용도로 다 쓰이고 있어서요.

결정 B

대화 목록 화면에도 “이 대화는 모델이 섞여 있음”을 표시할까요?

대화 목록은 수십~수백 개 대화를 한눈에 훑는 화면입니다. 지금은 대화 하나당 모델 이름표가 정확히 1개씩 붙습니다.

지금 — 실제론 모델 3개를 썼는데 하나로만 보임
ClaudeOpus 4.8 4.6M 토큰
제안 — 이름표 하나 안에서 해결
ClaudeOpus 4.8  +2 4.6M 토큰

Claude 대화 78개 중 33개(42%)가 실제로는 여러 모델을 썼는데, 목록에서는 전부 단일 모델처럼 보입니다.

이름표에 +2 붙이기

→ “목록에도 표시해”

  • 목록이 거짓말을 안 하게 됨 — 42%가 실제와 다르게 보이는 문제 해소
  • 새 이름표를 추가하지 않고 기존 것에 글자만 붙여서, 좁은 화면에서 줄이 넘치지 않음

목록은 그대로 두기

→ “대화 안에서만 보여줘”

  • 바꾸는 범위가 좁아짐
  • 다만 목록에서는 여전히 42%가 단일 모델처럼 보임 — 대화를 하나씩 열어봐야 알 수 있음

두 가지만 정해주시면 명세 문서를 쓰고 8단계 구현에 들어갑니다. 구현은 각 단계가 독립적으로 되돌릴 수 있게 쪼개져 있고, 첫 단계는 코드를 전혀 건드리지 않습니다.

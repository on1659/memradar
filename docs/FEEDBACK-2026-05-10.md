**목표:** Wrapped 진입의 가장 큰 두 이질감(보이지 않는 스킵 버튼, 한글 fallback "궁서체")을 정확하게 해결한다. 단순 시각 보정이 아니라 **타이포그래피 토큰을 디자인 시스템으로 정착**시키는 작업.

#### 1A. 스킵 버튼 시인성 강화

- **수정 파일:** `src/components/wrapped/WrappedView.tsx` + (신규) 타이포·컨트롤 토큰 정의 위치 합의 후 토큰화.

#### 1B. Instrument Serif 한글 fallback 제거

- **수정 파일:** Wrapped 슬라이드 9개의 인라인 `style={{ fontFamily }}` 모두 + `src/index.css` 의 `h1, h2` Noto Serif KR 룰 + (필요 시) 새 Tailwind 폰트 클래스 정의.

#### 4A. DropZone 분석 단계 시각화

  - 큰 숫자(PromptsSlide 카운트업 등)는 정보 인지가 가능한 호흡 유지.
  - 모션 토큰이 다른 슬라이드/Dashboard 모달에서 재사용 가능.

**예상 트리아지:** **COMPLEX** (분석 진행률 데이터 모델 영향 + Wrapped 다수 + 신규 컴포넌트 + 모션 토큰 시스템).

### 4.3 옛 옵션 비교 (참고용 — 결정 후 보존)

> 결정 시점의 옵션 비교를 보존하여 향후 재논의 시 컨텍스트 제공. 본 섹션은 변경 금지.

### Q1. 스킵 버튼 톤 (묶음 1A)

- **A) 솔리드 흰색 배경:** 시인성 최대. 단, 어두운 슬라이드 위 흰 솔리드는 톤 충돌 가능.
- **B) 액센트 보라:** 시각 우선순위 명확. 단, 동석 지님의 "남색/보라 빼기" 기조와 충돌 가능.
- **C) 흰 윤곽 + 반투명 배경:** 톤 다운 기조와 정합. 시인성도 §1 검수 기준 충족 가능.
- **결정 근거:** 슬라이드 그라디언트 위에서의 시인성 + 디자인 시스템 컨트롤 토큰과의 일관성.

### Q2. 폰트 전략 (묶음 1B)

- **A) Pretendard 일원화 (Serif 완전 제거):** 한글/영문 톤 통일, 디스플레이 폰트가 갖는 AI 슬롭 시그니처 제거.
- **B) 영문 Instrument Serif + 한글 Pretendard Black:** 영문 Wrapped 무드 일부 보존, 한글 fallback 문제 해결. 단, 폰트 2종 혼용은 동석 지님 "폰트 글마다 다름" 지적과 충돌 가능 → 룰의 명확성이 더 중요해짐.
- **C) 한글 디스플레이 폰트 새 도입 (예: IBM Plex Sans KR Bold):** 정체성 강화 + fallback 해결. 폰트 라이선스/로딩 비용 검증 필요.
- **결정 근거:** 한 화면 안의 톤 통일 + Wrapped 정체성 + 라이선스/로딩 비용.

### Q3. 액센트 컬러 (묶음 3A)

- **A) 보라 `#7c6ff7` 유지:** 기존 자산(스크린샷/문서/테마) 일관성 유지.
- **B) 중성 톤(흰색/오프 화이트/그레이)으로 대폭 축소:** 동석 지님 기조와 정합. 단, 정보 위계가 농도만으로 충분한지 검증 필요.
- **C) 다른 액센트로 교체:** 새 정체성 수립. ThemeSwitcher 옵션과의 정합성 점검 필요.
- **결정 근거:** 정보 위계 표현력 + 동석 지님 톤 다운 의도 + 테마 시스템 정합성.

### Q4. 카테고리 컬러 9종 (묶음 3A)

- **A) 다채색 유지 (정보 구분 우선):** 카테고리 식별성 최대.
- **B) 모노크롬 + 진행 바 농도:** 톤 다운 기조와 정합. 단, 9개 카테고리를 농도만으로 구분 가능한지 사용성 검증 필요.
- **C) 2~3톤 제한 팔레트:** 절충안. 카테고리를 그룹핑(예: 코드 작업/배포/문서)해 톤으로 묶음.
- **결정 근거:** 새 SVG 아이콘 형태가 카테고리 식별을 얼마나 담당하는지 + 톤 다운 강도.

### Q5. 로딩 연출 (묶음 4A)

- **A) 단계 체크리스트:** 진척도 명확. 단, 분석 단계가 짧은 시간 안에 지나가면 깜빡임 → 최소 노출 시간 보장 필수.
- **B) 카운트업 + 미니 통계 미리보기:** 동적이라 답답함 해소. Wrapped 첫 슬라이드(PromptsSlide)로 매끄러운 연결. 진척도 데이터 모델 정확히 잡아야 함.
- **C) 미니멀 스피너 + 메시지 로테이션:** 가장 단순. 단, "답답함" 자체에 대한 근본 해결력은 약함.
- **결정 근거:** 분석 시간이 길어질 때(대용량 세션)의 사용자 인내 + 분석 데이터 모델과의 정합 + Wrapped 첫인상 연결성.

### Q6. 작업 순서

- **A) 묶음 1 → (Codex 의뢰 송부) → 묶음 2 → 3 → 4:** 톤이 합의된 1을 먼저 끝내고, 동석 지님 1차 검수 → Codex 결과물 도착 시 묶음 2로 진입. **리스크 분리·검수 회수 확보** 노선 (속도가 아닌 품질 노선).
- **B) Codex 의뢰부터 송부 후 1·3·4 병행, 결과물 도착 시 2 진입:** 의뢰 대기 시간을 다른 묶음 작업으로 활용. 단, 1B(폰트)·3(컬러)·4B(모션) 가 묶음 2의 시각 시스템에 의존하므로 후수정 가능성.
- **결정 근거:** 검수 회수 + 후수정 리스크 + 동석 지님 검토 회수.

### Q7. 동석 지님 검토 회수

- **A) 묶음별로 단계 공유:** 톤 어긋남을 일찍 감지 가능. 동석 지님 시간 점유는 늘어남.
- **B) 1+2 통과 후 1차 공유, 3+4 통과 후 2차 공유:** 검수 회수 최소화 + 큰 변화를 큰 단위로 합의.
- **C) 4개 묶음 통과 후 1회만:** 큰 변경을 한 번에 — 톤 어긋남 발견 시 재작업 비용 큼.
- **결정 근거:** 톤 어긋남 조기 감지 + 동석 지님 시간 효율 + 재작업 비용.
